<objective>
Deliver the HTTP document lifecycle for Phase 4: a mutex-protected in-memory document store keyed by server-generated UUID v4, `POST /api/documents` (multipart upload -> magic-byte + size/page validation -> pdfcpu extraction -> OCR all pages -> JSON), `GET /api/documents/{id}/pages/{n}` (PNG preview), and `DELETE /api/documents/{id}` (remove document + artifacts). No editing/rebuild (Phase 5) and no persistence. Implements D-01..D-07.

Purpose: Isolate the HTTP touch point behind the existing `pdfio` and `ocr` packages so Phase 5 can call `Store.Get` and edit pages without knowing upload/preview details. The main correctness risks are data races on the store, holding the mutex during slow I/O, and leftover temp artifacts on partial failure.

Output: `internal/api` package (store, ids, handlers, tests) plus updated `cmd/server/main.go` wiring.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> API | Untrusted multipart upload crosses here; size/page/magic validation applied |
| API -> filesystem | Server writes temp dirs and extracted images; paths sourced from store, not user input |
| API -> OCR process | Image path from store passed to Tesseract; no user-controlled path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of Service | upload handler | medium | mitigate | http.MaxBytesReader 50 MiB cap + connection close on overflow |
| T-04-02 | Tampering | upload handler | medium | mitigate | Magic-byte check `%PDF-` + pdfapi.PageCountFile parse validation |
| T-04-03 | Tampering | getPage/deleteDoc | high | mitigate | `id` used only as map key (404 if unknown); `n` parsed as int with range check; file path sourced from store (no traversal) |
| T-04-04 | Information Disclosure | multipart handling | low | mitigate | defer r.MultipartForm.RemoveAll() + per-doc dir with deferred cleanup on failure |
| T-04-05 | Tampering | Store map | high | mitigate | sync.Mutex on all map access; verified by go test -race |
| T-04-06 | Information Disclosure | deleteDoc | low | accept | Best-effort os.RemoveAll; log on failure; document removed from store regardless |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages in Phase 4 (stdlib + existing internal only); package-legitimacy gate satisfied (audit table in RESEARCH.md) |
</threat_model>
